## PRE-FLIGHT

Исходный HEAD: `f93af020059c4dc0c869029c963490eee6012ab1`, ветка `feat/wp-driven-seo-metadata`, рабочее дерево до изменений чистое. Архив `client51.zip` в проверенных расположениях Downloads и Practic не найден; побайтовое сравнение с ним не выполнено. Ориентиры brief сверены с фактическим repository. Более новая URL-пагинация каталога не меняет PDP data flow.

Подтверждены существующие механизмы:

- `wordpress/mu-plugins/door-product-configuration.php`: registry и разрешение accessory policy по категориям, семейству и товару; `category` / `explicit` / `disabled`.
- `src/lib/woo/products.ts`: загрузка разрешённых product ID, сортировка групп по Woo `menu_order`, товаров по `sortOrder`, затем имени. Группы без товаров уже исключаются сервером.
- `DoorProductConfigurator`: выбор фурнитуры хранится по product ID независимо от отображения; все выбранные позиции включаются в цену и `CartItemInput`.
- `CartProvider`: localStorage, объединение по `itemKey`, лимит 99 на одну комплектацию и `totals.itemsCount` как сумма количества комплектов. Возврат `addItem()` — подготовленная позиция, а не результат объединения; UI ждёт обновлённого `items`.
- Checkout уже допускает количество фурнитуры 0–99 и комплектов 1–99. PDP приводит ввод к этим целым диапазонам. Ограничения числа разных комплектаций, позиций фурнитуры и обработка неизвестной цены сохраняются.
- Header выводит одну toolbar-ссылку корзины на desktop/mobile; sticky включается при прокрутке вверх после 400 px. В мобильной панели есть дополнительная сводка.
- `ContentHtmlWithLightbox` работает с WP HTML, но не обеспечивает нужный modal/focus lifecycle для обычной товарной фотографии. Новый небольшой Lightbox использует native `dialog`, без зависимости от WP HTML или новой библиотеки.
- Общий `.input-step` уже скрывал WebKit-стрелки. PDP получает собственный CSS для WebKit и Firefox.

Новые PHP/REST/BFF-механизмы и данные WP не нужны. Проверка неизвестных DB/admin-настроек для этого UI-шага не требуется. Во время проверки frontend использует существующие read-only GET LocalWP; DB/admin не изменяются.

- Вкладки строятся только из готового `product.accessories`, с прежним порядком. По уточнению пользователя показываются название группы и индикатор выбранных позиций, без числа доступных товаров. Клавиши ←/→, Home/End переключают вкладки; на узком экране полоса прокручивается. В DOM остаются строки только активной группы, количества остальных групп сохранены в конфигураторе.
- Миниатюры 96×72 используют `contain`. Кнопка с лупой открывает тот же URL в modal `dialog`; фото ограничено естественным размером, максимум 400 px по ширине и размером viewport. Закрытие кнопкой, Escape и фоном; фокус возвращается на миниатюру без прокрутки. Фоновая прокрутка блокируется с компенсацией scrollbar. Заглушка не интерактивна.
- Оба PDP-счётчика сохраняют ручной ввод и кнопки, получают подписи и видимый keyboard focus; некорректный ввод нормализуется в прежний диапазон checkout.
- `IntersectionObserver` следит именно за toolbar-ссылкой Header, включая sticky. При её уходе из viewport появляется компактная корзина с `totals.itemsCount`; после гидратации используется сохранённое количество. При открытом мобильном меню dock скрыт.
- Единственное уведомление после добавления использует фактическую разницу количества позиции после reducer. Показывает добавленное количество, актуальное общее количество и «Посмотреть корзину». Частичное добавление и отказ на лимите описаны явно. Через 8 секунд уведомление сворачивается; hover/focus приостанавливают таймер. Видимая корзина Header получает краткую подсветку с учётом `prefers-reduced-motion`.
- Если dock пересекает область количества комплектов / кнопки добавления, он перемещается вверх, ниже видимой шапки. Навигация в корзину остаётся добровольной.
- По дополнительному уточнению пользователя автопоказ демо-уведомлений о покупках `#pop-main` отключён в общем `PopupPage`: `autoShow` по умолчанию `false`, начальный таймер и автоскрытие не запускаются, карточки скрыты. Тег, разметка и существующие подключения в корзине, checkout и разделах стеновых панелей сохранены. Будущее явное включение возможно через `<PopupPage autoShow />`; сейчас таких вызовов нет. Это отключение не затрагивает подтверждение реального добавления комплекта в корзину.

CartProvider, CartItem/CartItemInput, itemKey, расчёт цен, логика checkout, PHP, REST corpus, маршруты и SEO не изменяются. Переключение вкладок и открытие фото не выполняют дополнительных Woo/WP-запросов.

## Выпуск и возврат

Тип изменения — frontend code + эксплуатационная документация. Новых зависимостей, env, PHP, миграций, ACF definitions/values, policy, uploads и инфраструктурных изменений нет.

Использовать существующий combined release по `change-based-release-guide.md` и no-DB runbook: после отдельного разрешения на commit/merge/deploy выбрать принятый SHA из main, выпустить его штатным `deploy-environment.sh` сначала на staging, проверить сценарии ниже и затем отдельно согласовать production. Managed MU-code входит в обычный release того же SHA; специальных операций WP для этого шага нет.

Нельзя импортировать Local/Staging DB или менять живые заказы. При возврате использовать предыдущий совместимый code release штатным runbook без восстановления БД. Ключ и формат localStorage сохранены, существующая корзина совместима с предыдущим кодом.

Deploy shell scripts не требуют изменения: runtime-контракт прежний. Общий HTTP smoke проверяет доступность, health и indexing, но не подтверждает клиентские вкладки/Lightbox/localStorage; нужна отдельная браузерная приёмка PDP. В рамках задачи commit, merge и deploy не выполняются.

## Ручная приёмка data → UI → cart → checkout

1. Открыть PDP с несколькими policy-группами. Сверить группы и товары с существующими Woo/policy данными и порядком `menu_order`; новая разрешённая группа должна появляться без правки frontend. Пустая фурнитура должна показывать понятное сообщение.
2. Выбрать 2 петли, переключиться на ручки и выбрать 1 ручку. Вернуться: петли остаются 2, итог и сводка включают обе группы. Повторить клавиатурой и на ширине 320/390 px, проверить горизонтальную прокрутку вкладок и таблицы без расширения страницы.
3. Проверить миниатюру 96×72 без обрезки, лупу на hover/focus и touch. Открыть фото: размер не превышает исходный и viewport. Проверить кнопку закрытия, Escape, фон, удержание фокуса внутри modal, возврат фокуса и позиции страницы. Не должно теряться количество/опции; «Нет фото» не открывает modal.
4. Проверить ± и ввод для обоих счётчиков: пустое, 0, отрицательное, дробное, 99 и больше 99. После обработки остаются целые 0–99 / 1–99; в Firefox/Chromium/Safari нет нативных стрелок; клавиатурный focus виден.
5. Добавить комплект с фурнитурой из разных вкладок. Сверить уведомление, число комплектов, Header, компактную корзину и `/shopping-cart`. Повторное добавление объединяет прежнюю комплектацию; другая опция/фурнитура создаёт другую позицию.
6. Для существующей позиции 98 добавить 2: фактически добавлен 1, итого 99, сообщение объясняет лимит. Повторить добавление при 99: успех не заявлен. Общий счётчик нескольких комплектаций может быть больше 99.
7. Прокрутить вниз, затем вверх до sticky Header; проверить переключение видимости dock по реальной видимости корзины. Проверить мобильное меню, отсутствие перекрытия кнопки добавления, уменьшенную высоту экрана, поворот устройства и виртуальную клавиатуру.
8. Убедиться, что уведомление доступно через status/live, ссылка ведёт в корзину, автоперехода/прокрутки нет; таймер сворачивает его, hover/focus сохраняют доступность. Повторить с reduced motion.
9. Перезагрузить PDP и корзину: после гидратации количество сохраняется. Перейти к checkout и сверить опции, фурнитуру, количества и итог. Товар без известной цены сохраняет прежнее поведение. Успешную отправку заказа выполнять только отдельным согласованным тестом.
10. Проверить консоль и Network: переключения вкладок и фото не добавляют Woo/WP GET; checkout/BFF и canonical/metadata не изменились.
11. Открыть корзину, checkout, список стеновых панелей и страницу панели на desktop; подождать больше 2 секунд и повторного 5-секундного интервала. Карточки `#pop-main .pop-up` не должны появляться, сам контейнер остаётся в DOM. Подтверждение реального добавления в корзину на PDP работает отдельно.

## Риски и границы

- Автоматические серверные тесты и HTTP smoke не заменяют Safari/Firefox, touch-устройство и screen reader. Native modal `dialog`, IntersectionObserver, ResizeObserver и CSS `:has()` требуют современных браузеров.
- Высота групп различается; переключение меняет высоту блока, не сбрасывая выбранные количества. Таблица сохраняет горизонтальную прокрутку на узких экранах.
- Качество увеличения ограничено существующей фотографией (обычно 400×300). Отсутствующий/недоступный media URL нельзя исправить UI-увеличением.
- Существующие checkout-лимиты числа позиций и запрет неизвестных цен этим шагом не пересматриваются.
